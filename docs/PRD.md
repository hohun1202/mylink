## 1. 개요

### 1.1 한 줄 정의
개인 크리에이터와 일반 사용자가 **자기 프로필과 여러 링크를 한 페이지에 모아** `mylink/<핸들>` 주소로 공유하는 링크 & 바이오 프로필 서비스. (링크트리 클론)

### 1.2 이번 버전(MVP)의 목표
- **수업 과제·포트폴리오용 데모.** 가입 → 핸들 설정 → 프로필·링크 편집 → 공개 페이지 확인까지 **실제로 조작 가능한 흐름**을 보여주는 것이 목표.
- 결제, 운영(신고·관리자), 약관 등 실서비스 요소는 제외.

### 1.3 구현 전제 (중요)
| 항목 | 결정 |
|---|---|
| 아키텍처 | **클라이언트 전용** — 백엔드 서버·DB 없음 |
| 데이터 | **Mock 데이터 + 브라우저 LocalStorage** 에 저장. Mock 데이터는 `src/mocks/` 의 JSON을 쓴다 (5.2절) |
| 인증 | **선택 기능(P1)** — 구현 시 가짜 구글 로그인 (실제 OAuth 아님). 미구현 시 브라우저별 로컬 사용자 1명 |
| 전역 상태 관리 | **Zustand** + `persist` 미들웨어 (LocalStorage 동기화) |
| 코드베이스 | 기존 `mylink` 프로젝트(Next.js 16 · React 19 · TypeScript · Tailwind CSS v4)를 서비스로 확장. git 기록 유지 |
| 디자인 시스템 | **shadcn/ui** (https://ui.shadcn.com) 컴포넌트 위에 **`design.md` 의 디자인 시스템**을 입혀 구축한다 (1.4절) |
| 스타일 작성 방식 | **Tailwind CSS 유틸리티 클래스로 통일.** CSS Module(`*.module.css`)은 쓰지 않는다 (1.4절 "스타일 작성 규칙") |

> **알려진 한계**: 데이터가 사용자의 브라우저에만 저장되므로, 다른 기기·다른 브라우저에서 `mylink/<핸들>` 에 접속하면 해당 페이지가 보이지 않는다. 데모 목적상 허용한다.

### 1.4 디자인 시스템 — shadcn/ui + `design.md`

앞으로 모든 화면 디자인은 **shadcn/ui를 기반으로, `design.md` 에 정의된 디자인 시스템처럼 보이도록** 구축한다.

| 역할 | 담당 |
|---|---|
| **구조·동작·접근성** (컴포넌트 종류, 키보드 조작, 스크린리더 지원) | shadcn/ui |
| **겉모습** (색상, 글꼴, 모서리 둥글기, 그림자, 간격, 컴포넌트별 모양) | `design.md` |

- 즉 shadcn/ui 컴포넌트를 그대로 쓰되, 그 **디자인 토큰(CSS 변수)과 variant 를 `design.md` 의 값으로 바꿔서** `design.md` 의 디자인처럼 보이게 만든다.
- `design.md` 와 shadcn/ui 기본 스타일이 다르면 **`design.md` 가 우선**한다.
- `design.md` 의 위치: **미정 — 10장 미결정 사항 7번.** 확정되면 `docs/design.md` 에 두는 것을 기본안으로 한다.

**설정 (2026-09-22 초기화 완료, `components.json`)**

| 항목 | 값 |
|---|---|
| 초기화 명령 | `npx shadcn@latest init -d` (공식 기본 설정) |
| 스타일 프리셋 | `base-nova` (내부 컴포넌트 라이브러리: Base UI) |
| 기본 색상 | `neutral` |
| 색상 방식 | CSS 변수 (`--background`, `--primary` 등, `src/app/globals.css`) |
| 아이콘 | `lucide-react` |
| 컴포넌트 위치 | `src/components/ui/` |
| 유틸 함수 | `src/lib/utils.ts` 의 `cn()` |

**Tailwind CSS v4 전제**
- `tailwind.config.js` 파일은 **만들지 않는다.** 디자인 값(색·반경·글꼴)은 `globals.css` 의 `@theme` 블록과 CSS 변수로 관리한다.
- `postcss.config.mjs` 는 Next.js와 Tailwind를 연결하는 파일이므로 유지한다.

**스타일 작성 규칙 — Tailwind CSS로 통일**
- 모든 화면·컴포넌트의 스타일은 **JSX의 `className` 에 Tailwind 유틸리티 클래스로만** 쓴다.
- **CSS Module(`*.module.css`)을 만들지 않는다.** 컴포넌트별 CSS 파일, `style={{…}}` 인라인 스타일도 쓰지 않는다.
- 조건에 따라 클래스를 바꿀 때는 `cn()` 으로 합치고, 같은 모양이 반복되면 `cva` variant(shadcn `ui/` 컴포넌트)로 묶는다 (아래 작업 규칙 5).
- CSS 파일은 `src/app/globals.css` 하나만 둔다. 여기에는 **디자인 토큰(CSS 변수)·`@theme`·전역 기본값**만 두고, 화면별 클래스(예: 기존 `.plate`, `.chip`, `.hero-wordmark`)를 새로 추가하지 않는다. 기존 전역 클래스는 새 화면에서 쓰지 않는다.
- Tailwind만으로 표현하기 어려운 값은 먼저 토큰으로 추가한 뒤 클래스로 쓴다. 임의값 클래스(`w-[123px]` 등)는 최소한으로만 쓴다.

**작업 규칙**
1. **shadcn/ui에 있는 컴포넌트를 먼저 쓴다.** 필요한 컴포넌트는 `npx shadcn@latest add <이름>` 으로 추가한다. 같은 역할의 컴포넌트를 직접 새로 만들지 않는다.
2. 여러 컴포넌트를 조합한 화면 단위 컴포넌트(예: 링크 버튼 목록, 프로필 헤더)는 `src/components/` 에 두고, 그 안에서 `ui/` 컴포넌트를 조립한다.
3. **`design.md` 의 값은 먼저 토큰으로 옮긴다.** 색·반경·글꼴·그림자는 `globals.css` 의 shadcn CSS 변수(`--background`, `--foreground`, `--primary`, `--secondary`, `--muted`, `--accent`, `--destructive`, `--border`, `--ring`, `--radius` 등)와 `@theme` 블록에 매핑한다. `design.md` 에 있지만 shadcn 기본 토큰에 없는 값은 새 CSS 변수로 추가한다.
4. **화면 코드에서는 토큰만 쓴다.** 컴포넌트 안에 16진수 색(`#e60012` 등)이나 임의 크기를 직접 쓰지 않고, 의미 토큰 클래스(`bg-background`, `text-foreground`, `bg-primary`, `text-muted-foreground`, `border-border` 등)를 쓴다.
5. **컴포넌트 모양이 `design.md` 와 다르면** `src/components/ui/` 의 해당 컴포넌트에서 variant 를 고치거나 추가한다(예: `design.md` 의 버튼 모양을 `Button` 의 variant 로). 같은 모양을 화면마다 `className` 으로 반복해서 덮어쓰지 않는다.
6. 새 라이브러리를 설치할 때는 최신 버전을 쓴다. 단, 함께 쓰는 도구와 호환되지 않는 메이저 버전은 제외한다.

**기능별 사용 컴포넌트 (기본안)**

| 기능 | shadcn/ui 컴포넌트 |
|---|---|
| 링크 버튼 (F8) | `Button` 의 `buttonVariants` — `variant: "outline"`, `size: "block"`(가로 꽉 채움·긴 제목 줄바꿈, 2026-09-22 추가)을 `<a>` 에 적용 (+ lucide 아이콘) |
| 아바타 (F4·F8) | `Avatar` — 공개 페이지는 `size="xl"`(96px, 2026-09-22 추가) |
| 프로필·링크 편집 입력 (F4·F5) | `Input`, `Label`, `Textarea`, `Field` |
| 링크 삭제 확인 (F5) | `AlertDialog` — 브라우저 기본 `confirm()` 대신 |
| 대시보드 영역 구분 | `Card`, `Separator` |
| 테마 선택 (F6) | `RadioGroup` 또는 `ToggleGroup` |
| 저장 완료 알림 | `Sonner` (토스트) |

**테마 프리셋 (F6) 구현 방향**
- 테마마다 shadcn CSS 변수(`--background`, `--primary` 등)의 값 묶음을 하나씩 정의하고, 공개 페이지에 적용한다. 컴포넌트 코드는 테마별로 바꾸지 않는다.
- 기본 테마는 `design.md` 의 디자인이다. 나머지 프리셋도 `design.md` 의 규칙(글꼴·반경·간격 등)은 유지하고 색 묶음만 바꾸는 것을 기본안으로 한다.

**기존 디자인과의 관계**
- 기존 `globals.css` 에는 "Nintendo.com 2001 메탈릭 크롬" 스타일 변수(`--color-canvas`, `--color-primary: #e60012` 등)가 shadcn 변수와 따로 남아 있다. 새로 만드는 화면에서는 이 변수를 직접 쓰지 않는다.
- 이 스타일이 `design.md` 의 디자인과 같은 것인지는 미정이다 (10장 미결정 사항 7번). 같다면 이 값들을 shadcn 토큰으로 옮기고, 다르면 `design.md` 로 대체한다.

## 2. 대상 사용자

| 사용자 | 설명 | 주요 행동 |
|---|---|---|
| **페이지 주인** | 크리에이터·일반 사용자 | (선택) 로그인, 프로필·링크 편집, 테마 선택, 핸들 변경 |
| **방문자** (비로그인) | 공유된 링크로 들어온 사람 | 공개 프로필 페이지 열람, 링크 클릭 |

### 2.1 사용자 시나리오

#### 시나리오 A. 방문자 — 다른 사람의 마이링크 페이지 방문 (관련: F8 · 1단계)

1. 사용자는 관심 있는 크리에이터의 링크를 모아 보기 위해 SNS 프로필에 적힌 마이링크 주소(`mylink/<핸들>`)를 누른다.
2. 사용자는 올바른 사람의 페이지에 들어왔는지 확인하기 위해 페이지 맨 위의 아바타·이름·한 줄 소개를 본다.
3. 사용자는 원하는 콘텐츠를 찾기 위해 링크 버튼 목록을 위에서 아래로 훑어본다.
4. 사용자는 해당 콘텐츠로 이동하기 위해 원하는 링크 버튼을 누른다.
5. 사용자는 다른 링크도 이어서 보기 위해 새 탭으로 열린 페이지를 둔 채 마이링크 탭으로 돌아온다.

**예외 흐름**
- A-1. 사용자는 페이지를 찾기 위해 잘못된 핸들 주소로 접속했다가, "페이지를 찾을 수 없어요" 안내를 보고 주소가 틀렸음을 확인한다.

#### 시나리오 B. 소유자 — 자신의 마이링크 링크 관리 (관련: F4·F5 · 2단계)

> 로그인은 선택 기능(P1)이므로, 아래는 로그인 없이 브라우저의 로컬 사용자로 관리하는 흐름을 기준으로 한다.

**B-1. 대시보드 들어가기**
1. 사용자는 자기 페이지를 편집하기 위해 마이링크에 접속해 '대시보드로 가기' 버튼을 누른다.
2. 사용자는 현재 상태를 파악하기 위해 대시보드에 표시된 자신의 링크 목록을 확인한다.

**B-2. 링크 추가**
1. 사용자는 새 콘텐츠를 알리기 위해 대시보드에서 '링크 추가' 버튼을 누른다.
2. 사용자는 방문자에게 보일 버튼 이름을 정하기 위해 제목 입력칸에 제목을 입력한다.
3. 사용자는 버튼이 이동할 곳을 지정하기 위해 URL 입력칸에 주소를 입력한다.
4. 사용자는 링크를 목록에 등록하기 위해 '저장' 버튼을 누른다.
5. 사용자는 추가가 제대로 됐는지 확인하기 위해 목록에 새 링크가 나타난 것을 본다.

**B-2 예외 흐름**
- 사용자는 링크를 저장하기 위해 '저장'을 눌렀지만, URL 형식이 잘못되어(예: `abc`, `https://`) 입력칸 아래 오류 메시지를 보고 주소를 고친다.
- 사용자는 링크를 저장하기 위해 '저장'을 눌렀지만, 제목이 비어 있어 오류 메시지를 보고 제목을 입력한다.

**B-3. 링크 수정**
1. 사용자는 오래된 정보를 바로잡기 위해 고치고 싶은 링크의 '수정' 버튼을 누른다.
2. 사용자는 바뀐 내용을 반영하기 위해 제목 또는 URL 입력칸의 값을 고친다.
3. 사용자는 수정 내용을 적용하기 위해 '저장' 버튼을 누른다. (추가와 같은 URL 유효성 검사가 적용된다)
4. 사용자는 수정이 반영됐는지 확인하기 위해 목록에서 바뀐 제목·주소를 본다.

**B-4. 링크 삭제**
1. 사용자는 더 이상 쓰지 않는 링크를 없애기 위해 해당 링크의 '삭제' 버튼을 누른다.
2. 사용자는 실수로 지우는 것을 막기 위해 화면에 뜬 확인 창에서 삭제할 링크가 맞는지 확인한다.
3. 사용자는 삭제를 확정하기 위해 확인 창의 '삭제' 버튼을 누른다. (마음이 바뀌면 '취소'를 눌러 목록으로 돌아간다)
4. 사용자는 삭제가 완료됐는지 확인하기 위해 목록에서 해당 링크가 사라진 것을 본다.

**B-5. 결과 확인**
1. 사용자는 방문자에게 어떻게 보이는지 확인하기 위해 '내 페이지 보기'를 눌러 공개 페이지(`/<핸들>`)로 이동한다.
2. 사용자는 변경 사항이 저장됐는지 확인하기 위해 페이지를 새로고침하고, 추가·수정·삭제 결과가 그대로 남아 있는 것을 본다.

## 4. 기능 요구사항

우선순위: **P0** = MVP 필수 / **P1** = 있으면 좋음(시간 남으면)

### F1. 랜딩 페이지 — `/` (P0)
- 서비스 소개 문구 + **'시작하기'** 버튼.
- 이미 핸들을 만든 사용자(로그인 구현 시: 로그인 상태)면 버튼이 **'대시보드로 가기'** 로 바뀐다.
- 기존 개인 자기소개 페이지(현 `src/app/page.tsx`)는 랜딩 페이지로 대체한다.

### F2. 가짜 구글 로그인 — `/login` (P1 · 선택)
> **로그인을 구현하지 않을 때의 동작 (P0 기준선)**: 브라우저마다 로컬 사용자 1명을 자동으로 만들어 쓴다. 랜딩의 '시작하기'를 누르면 핸들이 없으면 `/onboarding`, 있으면 `/dashboard` 로 바로 이동하며, `/login` 화면과 로그아웃은 없다.
> 로그인을 구현하면 아래 요구사항을 적용한다.

- "Google로 계속하기" 모양의 버튼 1개.
- 누르면 Mock 구글 계정으로 로그인된 상태가 되어 LocalStorage에 세션을 저장한다.
- 로그인 후: 핸들이 없으면 `/onboarding`, 있으면 `/dashboard` 로 이동.
- **로그아웃**: 대시보드에서 가능. 세션만 지우고 사용자 데이터는 남긴다.
- 인증 로직은 한 모듈에 모아, 추후 실제 OAuth로 교체하기 쉽게 한다.

### F3. 핸들 설정 — `/onboarding` (P0)
- 처음 시작할 때(로그인 구현 시: 첫 로그인 직후) 핸들을 직접 입력한다.
- 입력 중 실시간 검사:
  - 형식 규칙 (아래 기본안)
  - **중복 검사** — LocalStorage의 기존 사용자 핸들과 겹치면 불가
  - **예약어 금지** — 앱 경로와 겹치는 단어
- 완료 시 `/dashboard` 로 이동.

> 핸들 규칙 **기본안** (인터뷰에서 정하지 않음 · 변경 가능):
> - 영문 소문자, 숫자, 밑줄(`_`)만 허용 / 3~20자
> - 예약어: `login`, `onboarding`, `dashboard`, `settings`, `api`, `admin`

### F4. 대시보드 — 프로필 편집 (P0)
| 필드 | 입력 방식 | 규칙 |
|---|---|---|
| 프로필 사진 | **기본 아바타 중 선택** (파일 업로드 없음) | 아바타 이미지는 `public/` 에 포함 |
| 이름 | 텍스트 | 필수 · 최대 30자 (기본안) |
| 한 줄 소개 | 텍스트 | 선택 · 최대 80자 (기본안) |

- 저장하면 LocalStorage에 즉시 반영된다.

### F5. 대시보드 — 링크 관리 (P0)
- **추가**: 제목 + URL 입력. 저장 전에 **URL 유효성 검사**를 한다.
  - `http://` 또는 `https://` 로 시작하는 올바른 주소 형식이어야 한다 (`https://`가 없으면 자동으로 붙이는 방식도 허용 — 구현 시 결정)
  - 빈 값, 공백이 섞인 값, 도메인이 없는 값(예: `https://`)은 거부한다
  - 검사에 실패하면 저장하지 않고 입력칸 아래에 오류 메시지를 보여준다
- **수정**: 제목·URL 변경. 추가와 같은 URL 유효성 검사를 적용한다.
- **삭제**: 삭제 전 확인 (브라우저 기본 `confirm()` 대신 화면 내 확인 UI)
- **순서 변경**: 드래그 앤 드롭. 바뀐 순서가 공개 페이지에 그대로 반영된다.
- 제목은 필수 입력이다.

### F6. 대시보드 — 테마 선택 (P0)
- **미리 만든 테마 프리셋 중 하나를 선택**한다. 색·폰트 개별 조절은 없다.
- 프리셋 개수: 3~5개 (구체 목록은 디자인 단계에서 확정)
- 선택한 테마는 공개 페이지에만 적용된다.

### F7. 설정 — 핸들 변경 (P0)
- 대시보드에서 핸들을 바꿀 수 있다. F3과 같은 검사 규칙을 적용한다.
- 변경하면 기존 주소 `/<옛 핸들>` 은 더 이상 연결되지 않는다 (리다이렉트 없음).

### F8. 공개 프로필 페이지 — `/<핸들>` (P0)
- 구성 (위에서 아래 순서):
  1. 아바타
  2. 이름
  3. 한 줄 소개
  4. 링크 버튼 목록 (저장된 순서대로) — 각 버튼은 **아이콘 + 제목 + 이동 표시(`>`)**
- 링크 버튼을 누르면 **새 탭**에서 열린다. 버튼 전체가 눌리는 영역이다.
- 선택된 테마를 적용한다.
- 모바일 우선 반응형.
- 페이지 주인이 보고 있으면 상단에 **'편집하기'** 바로가기를 띄운다 (P1).
- 하단에 작은 글씨로 서비스 표시("made with mylink")를 둔다 (P1).
- 존재하지 않는 핸들: **"페이지를 찾을 수 없어요"** 안내 문구를 보여준다. (별도 디자인의 전용 안내 화면·'내 페이지 만들기' 버튼은 범위 밖)

#### 링크 아이콘 규칙 — URL로 자동 결정
- 사용자가 아이콘을 고르지 않는다. **링크 URL을 보고 아이콘을 자동으로 정한다.**
- 따라서 데이터에 아이콘을 저장하지 않는다 (5장 `Link` 에 `icon` 필드 없음). 표시할 때마다 URL에서 계산한다.
- 매칭 기본안 (구현 시 조정 가능):

| URL 조건 | 아이콘 |
|---|---|
| 주소에 `github.com` 포함 | GitHub |
| 주소에 `youtube.com` 또는 `youtu.be` 포함 | YouTube |
| 주소에 `instagram.com` 포함 | Instagram |
| 주소에 `x.com` 또는 `twitter.com` 포함 | X |
| 주소에 `velog.io` 또는 `blog` 포함 | 블로그 |
| `mailto:` 로 시작 | 메일 |
| 그 밖의 모든 주소 | 기본 링크 아이콘 |

#### 와이어프레임 (모바일 기준)

```
+--------------------------------------+
|  mylink.app/hohun1202                |  <- (0) 브라우저 주소창
+======================================+
|                                      |

|            |  AVATAR   |             |  <- (1) 프로필 이미지 (원형)

|                                      |
|  +--------------------------------+  |
|  | [BL]  Blog (velog)         >   |  |
```

|---|---|---|

| (2) | 이름 | 가장 크고 굵은 글씨 |

## 5. 데이터 모델 (LocalStorage)

```ts
// 키: "mylink:users"  → User[]
type User = {
  id: string;            // 내부 고유 ID
  email: string;         // Mock 구글 계정 이메일
  handle: string | null; // 온보딩 전에는 null
  name: string;
  bio: string;
  avatarId: string;      // 기본 아바타 식별자
  themeId: string;       // 테마 프리셋 식별자
  links: Link[];         // 배열 순서 = 화면 표시 순서
  createdAt: string;     // ISO 날짜
};

type Link = {
  id: string;
  title: string;
  url: string;           // 아이콘은 저장하지 않고 이 URL로 자동 결정 (F8 링크 아이콘 규칙)
};

// 키: "mylink:session" → { userId: string } | 없음
```

- LocalStorage 접근은 **하나의 저장소 모듈**로 감싸서, 나중에 실제 DB/API로 교체할 수 있게 한다.
- LocalStorage를 쓸 수 없는 환경(사생활 보호 모드 등)에서도 화면이 깨지지 않게 예외를 처리한다.

### 5.1 전역 상태 관리 — Zustand

| 항목 | 결정 |
|---|---|
| 라이브러리 | **Zustand** |
| 영속화 | `persist` 미들웨어로 위 LocalStorage 키에 자동 저장·복원 |
| 스토어 구성 | 사용자 데이터(`users`)와 세션(`session`)을 담당하는 스토어. 프로필·링크·테마·핸들 변경 액션을 스토어에 모은다 |
| 사용 위치 | 스토어를 읽는 컴포넌트는 클라이언트 컴포넌트(`"use client"`)로 둔다 |

**하이드레이션 요구사항 (필수)**
- 서버 렌더링 시점에는 LocalStorage가 없으므로, 서버 결과와 브라우저 결과가 달라 **하이드레이션 오류**가 날 수 있다.
- 스토어가 LocalStorage에서 **복원을 마치기 전에는** 사용자 데이터에 의존하는 화면(대시보드, 공개 페이지, 로그인 상태에 따른 이동)을 그리지 않고 로딩 상태를 보여준다.
- 복원 전 상태를 "데이터 없음"으로 판단해 `/login` 으로 튕기거나 404를 띄우지 않도록 한다.
- 구현 전 이 프로젝트의 Next.js 16 문서(`node_modules/next/dist/docs/`)에서 클라이언트 컴포넌트 관련 변경점을 확인한다.

### 5.2 더미(Mock) 데이터 — `src/mocks/`

화면 개발·시연에는 **`src/mocks/` 의 JSON 더미 데이터**를 사용한다. 파일별 상세 설명은 `src/mocks/README.md`.

| 파일 | 형태 | 용도 |
|---|---|---|
| `src/mocks/db.json` | 백엔드 DB 모양 — `users`, `links` 두 컬렉션. 링크는 `userId` 로 주인, `order` 로 순서를 가리킨다 | **초기 데이터의 원본.** LocalStorage가 비어 있을 때 이 값을 5장 `User` 모양(링크를 `order` 순으로 `links` 배열에 넣음)으로 바꿔 넣는다 |
| `src/mocks/api/*.json` | API 응답 모양 — 성공 `{ "data": … }`, 실패 `{ "error": { code, message, fields? } }`. 파일명 `메서드_경로.상태코드.json` | 나중에 실제 서버/API로 바꿀 때의 **요청·응답 형식 기준** |

**Mock 사용자 (각자 확인할 상황이 정해져 있음)**

| 핸들 | 링크 | 확인할 상황 |
|---|---|---|
| `hohun1202` | 4개 | 실제 본인 링크 |
| `demo` | 10개 | F8 링크 아이콘 규칙 전부(Instagram·YouTube(`youtube.com`·`youtu.be`)·X·블로그(`velog.io`·`blog` 포함)·GitHub·메일·기본) + 아주 긴 제목 |
| `newbie` | 0개 | 링크·소개가 빈 공개 페이지 |
| (없음, `handle: null`) | 0개 | 핸들 설정 전 사용자 (F3 · `/onboarding` 이동) |

**규칙**
- 새 테스트 상황이 필요하면 코드 안에 값을 흩어 쓰지 않고 `db.json` 에 추가하며, 필요하면 `api/` 에 응답 예시를 함께 추가한다.
- `db.json` 필드는 5장 데이터 모델과 이름을 맞춘다. 5장 모델이 바뀌면 `db.json` 도 함께 고친다.
- 이메일·URL은 `hohun1202` 를 빼고 모두 가짜 값(`example.com`, `mylink_demo` 등)을 쓴다.
- `api/` 의 주소(`/api/profiles/<핸들>`, `/api/me/links` 등)는 **예시 설계**다. 클라이언트 전용 MVP에서는 실제로 호출하지 않는다.
- `src/lib/mockData.ts` 는 **`db.json` 을 읽어 화면용 모양으로 바꾸기만** 한다 (2026-09-22 변경, 중복 데이터 제거). 핸들이 `null` 인 사용자는 공개 페이지가 없으므로 뺀다.

## 7. 범위 밖 (MVP에서 하지 않음)

- 실제 인증(OAuth), 서버, 데이터베이스, 배포 후 기기 간 데이터 공유
- 이메일+비밀번호 가입

- 핸들 변경 시 옛 주소 리다이렉트
- 결제·유료 플랜, 신고·관리자 기능, 약관·개인정보 처리

## 8. 완료 기준 (데모 시나리오)

아래 시나리오가 한 브라우저에서 끊김 없이 동작하면 MVP 완료로 본다.

1. `/` 에서 '시작하기' → 핸들 설정 화면으로 이동 (로그인 구현 시 가짜 구글 로그인을 거침)
2. 핸들 입력 — 형식 오류·중복·예약어가 걸러지는 것을 확인
3. 대시보드에서 아바타 선택, 이름·소개 입력
4. 링크 3개 추가 → 1개 수정 → 1개 삭제 → 드래그로 순서 변경. 잘못된 URL(예: `abc`, `https://`)이 거부되는 것을 확인
5. 테마 변경
6. `/<핸들>` 에서 변경 사항이 모두 반영됐는지 확인. 링크 클릭 시 새 탭으로 열림
7. 새로고침해도 데이터 유지
8. 핸들 변경 → 새 주소로 페이지가 열리고 옛 주소는 404
9. (로그인 구현 시) 로그아웃 후 다시 로그인하면 기존 데이터 그대로

## 9. 단계별 개발 계획

시연을 위해 **한 단계씩** 만든다. 앞 단계가 끝나기 전에는 다음 단계 기능을 만들지 않는다.

| 단계 | 범위 | 만들지 않는 것 |

| **1단계 (현재 · 화면 구현됨 2026-09-22)** | **공개 프로필 페이지(F8)** — `/<핸들>` 에서 아바타·이름·한 줄 소개·링크 목록 표시 | 랜딩, 로그인, 핸들 설정, 대시보드(편집 기능 전체), 테마, 통계 |
| 2단계 | 대시보드 — 프로필 편집(F4), 링크 관리(F5) | 테마, 로그인, 통계 |
| 3단계 | 핸들 설정(F3)·핸들 변경(F7), 랜딩(F1), 테마 선택(F6) | 로그인, 통계 |
| 이후 | 가짜 구글 로그인(F2, 선택), 통계 등 추가 기능 | — |

### 9.1 1단계 상세 — 프로필 페이지
- **데이터 출처**: 편집 화면이 없으므로 **`src/mocks/db.json` 의 Mock 데이터**(5.2절)를 쓴다. LocalStorage가 비어 있으면 Mock 데이터를 넣고, 이후에는 LocalStorage 값을 읽어 화면에 표시한다.
- **상태 관리**: Zustand + `persist` 로 LocalStorage와 동기화한다 (5.1 하이드레이션 요구사항 적용).
- **화면**: F8 구성과 와이어프레임 그대로 — 아바타, 이름, 한 줄 소개, 저장 순서대로의 링크 버튼(URL 자동 아이콘 + 제목). 링크는 새 탭으로 열린다.
- **없는 핸들**: "페이지를 찾을 수 없어요" 안내를 보여준다.
- **스타일**: Tailwind 유틸리티 클래스만 사용 (1.4절 스타일 작성 규칙). CSS Module 없음.
- **구현 파일 (2026-09-22)**

| 파일 | 역할 |
|---|---|
| `src/app/[handle]/page.tsx` | 주소에서 핸들을 꺼내 `ProfileView` 에 넘김 |
| `src/components/ProfileView.tsx` | 화면 본체. 복원 전 "불러오는 중…", 없는 핸들 안내, 아바타·이름·소개·링크 목록. 링크가 0개면 "아직 등록된 링크가 없어요" |
| `src/components/LinkButton.tsx` | 링크 버튼 1개 (아이콘 + 제목 + `>`), 새 탭 열기 |
| `src/lib/linkIcon.ts` | URL → 아이콘 종류 (F8 링크 아이콘 규칙) |
| `src/lib/mockData.ts` | `db.json` → 화면용 프로필 변환 |

- **규칙 구현 시 조정한 점**: X 아이콘은 "주소에 `x.com` 포함" 대신 **도메인이 `x.com`(또는 그 하위 도메인)인지**로 판단한다. `box.com` 처럼 글자만 겹치는 주소가 X로 잘못 잡히지 않게 하기 위해서다. 검사 순서는 메일 → GitHub → YouTube → Instagram → X → 블로그 → 기본.
- **완료 기준**:
  1. `/hohun1202`, `/demo` 에 접속하면 각 Mock 프로필이 보이고, `/newbie` 는 링크 없이도 화면이 깨지지 않는다
  2. LocalStorage에 Mock 데이터가 저장된 것을 브라우저 개발자 도구에서 확인할 수 있다
  3. 개발자 도구에서 LocalStorage 값을 직접 고치고 새로고침하면 화면에 반영된다
  4. 링크 버튼을 누르면 새 탭으로 열린다. `/demo` 의 10개 버튼에 URL에 맞는 아이콘이 모두 알맞게 보이고, 긴 제목도 버튼 밖으로 넘치지 않는다
  5. 없는 핸들로 접속하면 안내 문구가 보인다
  6. 하이드레이션 오류가 콘솔에 나타나지 않는다
